# Научная память 1.0

Расширение существующего ANTONOVIUM, основанное на коммите `6bdc92d066b189998e732f7f13d158c571e568b9`. Исходные PDF/FB2 остаются в прежнем Yandex Object Storage. Авторизация и файловые Edge Functions не заменяются.

## Пользовательские действия

- Поиск открывается прежней кнопкой или Ctrl/⌘ K. Он ищет по содержимому PDF с текстовым слоем и FB2, библиографии, внутренним источникам, записям, цитатам, исследовательским линиям и рукописи. Есть фильтры книги, автора и области, точная фраза и сочетание слов. Регистр и е/ё игнорируются только при поиске.
- Охват индексирования раскрывается в поиске: очередь, обработанные страницы/абзацы, ошибки, частичный индекс, отсутствие текстового слоя. Индексирование можно приостановить и продолжить. Для сканов OCR не выполняется.
- Найденный фрагмент можно открыть в источнике, сохранить самостоятельной цитатой или открыть в одной из двух областей стола.
- В картотеке разделены цитаты и собственные рассуждения: интерпретации, аргументы, возражения, гипотезы и выводы. Категории и исследовательские связи назначает пользователь.
- Библиография относится к конкретному экземпляру файла. Автоматические сведения отличаются от ручных и подтвержденных. Разные издания объединяются в группу только вручную; их пагинация не смешивается.
- Буквальный текст сохраненной цитаты не редактируется вместе с комментарием. Для PDF фактическая страница файла хранится отдельно от подтвержденной пользователем страницы издания. Для FB2 используется глава, абзац и символьное смещение, а не экранная страница.
- При недоступном оригинале сохраненная запись остается доступной. Если буквальный текст не найден по ориентиру, читальный зал сообщает о переходе к ближайшему месту.
- Экспортируются текстовые подборки цитат, библиография в TXT/CSV и структурированный JSON с библиографией, записями, происхождением и связями. JSON не содержит исходных книг и полнотекстового индекса. Импорт сохраняет прежние записи при противоречиях.

## Индекс и приватность

Для облачных книг используются `av_memory_documents` и `av_memory_chunks`: PostgreSQL Russian Full Text Search с GIN, точная нормализованная фраза и фильтры автора/книги. Русская морфология доступна в облачном индексе. Локальный индекс использует буквальный поиск без морфологии в IndexedDB.

PDF.js извлекает текст постранично. FB2 разбирается существующим безопасным XML-парсером, затем индексируется по структурным абзацам. Пакеты фиксируются с устойчивыми идентификаторами, fingerprint и положением последней завершенной единицы. Повтор пакета не создает дублей. Неизмененные готовые индексы не требуют повторного скачивания оригинала. Ошибка одной книги не останавливает очередь.

Бюджет приложения для облачного индекса — **64 МиБ исходного извлеченного текста на владельца**. Это не тарифный лимит Supabase: служебные столбцы, tsvector и индексы занимают дополнительное место. При достижении бюджета обработка честно останавливается; ранее сохраненные фрагменты доступны. Безопасный предел разбора одного FB2 — 64 МиБ XML. Первичный разбор XML синхронный; последующая обработка уступает главный поток между главами и пакетами. PDF.js использует worker и существующую диапазонную загрузку.

Исходный извлеченный текст хранится отдельно от нормализованного поискового. Нормализация регистра, е/ё, пробелов и переносов PDF не меняет буквальную цитату. Автоматически извлеченный текст требует сверки с оригиналом.

RLS требует одновременно `auth.uid() = owner_id`, разрешенное членство и собственную готовую книгу. RPC работают с правами вызывающего пользователя и пустым `search_path`; прямые записи также проверяют триггеры. Чужой индекс, отключенный участник и анонимный запрос не получают доступа. Публичные оригиналы, сервисные ключи, внешние поисковые сервисы и модельные API не добавлялись.

У намеренно локальной книги индекс, новые цитаты и библиография остаются на устройстве. Локальные поля стола не отправляются в облачные настройки. Прежние записи не переименовываются и не помечаются задним числом. При разрешенном существующим механизмом переносе книги в облако ссылки на экземпляр, библиография и цитаты согласованно получают новый идентификатор; буквальный текст сохраняется.

## Библиографические шаблоны

Шаблоны редактируются пользователем и используют только заполненные поля. Они ориентированы на ГОСТ Р 7.0.100–2018 для описания и ГОСТ Р 7.0.5–2008 для ссылок. Автоматическое соответствие всем частным требованиям стандартов и конкретного журнала не заявляется. Незаданные издательство, год, ISBN и печатная страница не придумываются.

Официальные карточки стандартов: [ГОСТ Р 7.0.100–2018](https://protect.gost.ru/gost/details/389dfd5a-535a-458a-81c3-14b729b1cee1), [ГОСТ Р 7.0.5–2008](https://protect.gost.ru/gost/details/2eef7820-44bc-49a4-bf1f-fe51c54039dc).

## Проверки

Результаты актуального выпуска и ограничения среды фиксируются в `scientific-memory-validation.json`. `tests/memory-browser.html` и `tests/reader-browser.html` — локальные интеграционные стенды с синтетическими материалами. Они не включаются в production build.

SQL-проверка `scripts/memory-rls-test.sql` создает только временные синтетические записи внутри одной транзакции, проверяет права A/B и завершает ее `ROLLBACK`. Она не заменяет испытание двух настоящих авторизованных браузеров. Тест синхронизации двух React-рабочих пространств использует имитированный транспорт и также обозначен отдельно.
